# L1 · AI Agent 用户

给日常使用 WorkBuddy / Codex 等能加载 Skill 的 AI 工具的人。装一次，之后一句「帮我评教」就完事。

## 你需要准备

- 能加载 Skill 的 AI 工具（WorkBuddy、Codex 等）
- Python 3.8+（引擎只用标准库，**不需要 pip install 任何东西**）
- Edge 或 Chrome

## 安装（一次性）

### 方式 A：把链接丢给 AI，让它自己装（推荐）

不用找路径、不用复制文件夹。把下面这句发给你用的 AI：

> 把 https://github.com/wfcsilence/bnu-pjxt-auto 里的 `L1_Agent用户/browser-form-automation` 装成 skill。

它会自己 clone、复制到 `~/.workbuddy/skills/browser-form-automation/`、检查结构对不对，然后告诉你怎么验证。仓库根目录的 [`AGENTS.md`](../AGENTS.md) 就是给它看的安装说明，Codex 这类会读仓库说明文件的工具通常连这句话都不用。

### 方式 B：手动复制

把 `browser-form-automation/` 整个文件夹复制到 Skill 目录：

- **WorkBuddy 用户级**（推荐，所有项目可用）
  - Windows：`C:\Users\<用户名>\.workbuddy\skills\`
  - macOS：`~/.workbuddy/skills/`
- **项目级**：`{项目目录}\.workbuddy\skills\`

两种方式都要**重启 AI 工具**才识别。确认装好：对 AI 说「你有哪些 skill」，应该能看到 `browser-form-automation`。

## 使用

### 方式一：全自动（推荐）

直接说：

> 帮我批量评教

Agent **会先问你四个问题**（这是刻意设计的，评教提交后不能改）：

> 开始前确认一下要填的内容：
> 1. 选择题每题都选哪一项？好 / 较好 / 一般 / 较差 / 差（默认：好）
> 2. 需要改进的地方？（默认：无）
> 3. 突出优点是什么？（默认：无）
> 4. 打多少分？满分 100，填数字（默认：90）

回答后它会复述一遍，然后自己完成：启动调试浏览器 → 检查登录 → 逐门填写提交 → 报告结果。

如果你懒得逐条回，直接说「都用默认」或在一句话里写清（比如「全选较好，改进填：多讲案例，优点填：案例丰富，95 分」），它会跳过提问。

### 方式二：自己先把浏览器开好

1. 用**独立配置目录**启动浏览器（关键，别用默认 profile）：

   Windows（PowerShell / cmd）：
   ```
   "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" --remote-debugging-port=9222 --user-data-dir="%LOCALAPPDATA%\PJAuto\EdgeProfile"
   ```

   macOS：
   ```bash
   "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
     --remote-debugging-port=9222 \
     --user-data-dir="$HOME/Library/Application Support/PJAuto/ChromeProfile"
   ```

2. 在窗口里登录评教系统，打开课程列表页
3. 对 Agent 说：「用 browser-form-automation 完成评教」

> **为什么必须用独立目录**：新版 Chromium 系（Edge/Chrome 136+）会拒绝在默认 `User Data` 目录上开启调试端口，端口永远起不来。用独立目录的代价是首次要登录一次，之后长期保留，也不影响你平时用的浏览器。

### 方式三：自己敲命令

想完全手动控制时：

```bash
python scripts/run.py recipes/bnu-pjxt.json --pick 较好 --fill 无 --fill 无 --fill 95
```

- `--pick`：选择题选项（好 / 较好 / 一般 / 较差 / 差）
- `--fill`：填空内容，**按顺序重复传**，三个空就传三次；不传则用配方里的默认值
- 不传任何参数 = `好` + `无` / `无` / `90`

## Agent 内部做了什么

| 步骤 | 具体动作 |
|------|---------|
| 0 | **先问用户四项内容**（选项 + 三个填空），复述确认后才动手 |
| 1 | 读 `recipes/bnu-pjxt.json` 配方，把回答替换进 `js.fill_submit` 的 `__PICK__` / `__FILLS__` |
| 2 | `engine.py` 连 CDP：`GET /json` 拿 `webSocketDebuggerUrl` → 手写 WebSocket 握手 → `Runtime.evaluate` |
| 3 | 跑 `js.ready`，确认「已登录 + 列表已加载」（未登录直接报错，不误报成功） |
| 4 | 循环：`js.list` 探测待办数 → `js.click` 进入第 N 门 → `js.check` 确认有表单 → `js.fill_submit` 一次填完并提交 |
| 5 | 用**待办数是否减少**判断成功（提交会跳页，JS 返回值不可靠） |
| 6 | 完成后报告：填写内容 / 提交数 / 跳过数 / 剩余数 |

全程在页面上下文执行，不涉及截图、坐标、鼠标焦点——这正是它比 GUI 自动化稳定的原因。

## 验证结果

对 Agent 说「看看还剩几门待评教」，或自己在浏览器切到「已评教」标签核对。脚本输出 `剩余待办=0` 表示清空。

## 换成别的学校的评教系统

配方和引擎是分开的，**只改配方，不动 `scripts/`**。

1. 在目标站点打开填写页并登录
2. 对 Agent 说：

> 参考 recipes/bnu-pjxt.json 为新站点生成一份配方，需要 ready / list / click / check / fill_submit 五段 JS，保存为 recipes/xxx.json，然后运行它。

3. Agent 读页面 DOM 生成配方并试跑

配方字段含义见上一层 `README.md` 的「给 Agent 的接口说明」。

## 出问题怎么办

| 现象 | 解决 |
|------|------|
| Agent 说找不到 skill | 确认层级是 `skills/browser-form-automation/SKILL.md`，别多套一层文件夹 |
| `无法连接浏览器调试端口` | 浏览器没开调试端口，或开了但用的是默认 profile → 按方式二启动 |
| `调试浏览器里没有登录态` | 在调试窗口登录一次 |
| `列表页加载超时` | 网络慢，或站点地址变了 → 手动打开一次列表页 |
| `数量未减少，疑似提交失败` | 页面可能报错。重跑即可，已提交的会自动跳过 |
| 某门课被「跳过」 | 这门已经评过了，正常 |

## 已知限制

- 只适配北师大研究生评教系统。换站点需要新配方。
- 校外走 WebVPN 时 URL 会被网关改写，`list_url` 会失配，需要在配方里改成实际地址。
- 同一时间只能跑一份，别开两个 Agent 同时评。
- 调试端口开着时本机任何程序都能控制那个浏览器实例，用完可关掉窗口。
